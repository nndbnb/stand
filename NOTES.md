### 2. Решения по сборщику

- Источник: публичный API MOEX ISS; фильтр: `stock/shares/TQBR`.
- Режим `record`: опрос таблицы `marketdata` примерно раз в 10 секунд; запись только нового значения `SYSTIME` для каждой бумаги.
- Идемпотентный ключ: `moex:TQBR:{SECID}:{event_time}`.
- Время `SYSTIME` интерпретируется как `Europe/Moscow` и переводится в UTC (`event_time`). `received_at` — UTC-время сбора.
- Формат: `.jsonl.gz` по дате и часу **получения**.
- Восстановление: сохранённая позиция `data/raw/state/moex_record.json`; временные файлы `data/raw/state/wal/`, по закрытию — gzip-файлы. Проверка согласованности позиции и закрытых файлов — **TODO** после полного перезапуска стенда.
- Режим `backfill`: минутные свечи по бумагам, отдельные файлы `raw.history`, с пагинацией и ограничением частоты запросов.
- Повтор HTTP 429/5xx: пауза с увеличением задержки; журнал stdout в JSON.
- Предельный объём по заданию: 20 ГБ суммарно для сырого потока и истории; ротация по возрасту закрытых файлов.
- Дополнительное задание: HTTP `GET /metrics` на порту 9101. Рост счётчика ошибок при отключении сети ещё требуется подтвердить.
- Исправление v02: удалена ошибочная пагинация текущего блока `marketdata`, поскольку ISS повторял страницы при `start=512`. Текущие данные читаются одним запросом, исторические свечи по-прежнему постранично.

`event_time` сериализуется как Avro `long` с логическим типом `timestamp-millis`. Контрольный пример: `SYSTIME=2026-10-18 19:14:25` → `event_time=2026-10-18T16:14:25.000Z` → `1792340065000` мс Unix UTC.

**Ограничение сопоставимости размеров:** `NUMTRADES` намеренно исключён из Avro v1 для последующего добавления в Avro v2, поэтому полный JSONL и Avro v1 не содержат идентичного набора полей. Avro OCF записан без встроенного сжатия, а исходный JSONL.gz — со сжатием gzip: их размеры нельзя использовать как честное сравнение только форматов кодирования.

### DuckDB: исследование сырого слоя

Первый запуск `jobs/explore.sql` по всему `raw.stream` завершился с кодом **137** (SIGKILL; вероятная нехватка памяти, точная причина требует проверки журналов ядра). Результаты запросов не получены. Для воспроизводимого анализа скрипт ограничен тем же контрольным часом 2026-10-19 16:00–16:59 UTC, а DuckDB настроен на один поток и лимит 1024 MB. Результаты этого **часа** нельзя без оговорок распространять на весь накопленный поток.

Автотипизация: `SEQNUM`, `NUMTRADES`, `VOLTODAY` → `BIGINT`; рыночные цены преимущественно → `DOUBLE`; `SYSTIME` и `event_time` → `TIMESTAMP`; `UPDATETIME`, `TIME` → `TIME`. Поля, содержащие только `null`, распознаны как `JSON` (например, `BIDDEPTH`, `OFFERDEPTH`). Avro v1 задаёт явные типы и допускает `null` для необязательных полей. `event_time` в Avro хранится как `timestamp-millis` UTC, а в JSON представлен строкой.
