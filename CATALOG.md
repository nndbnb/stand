# Каталог данных платформы — вариант №12

**Статус:** рабочая версия по результатам ЛР1 на 12.10.2026. Каталог ведётся с ЛР1 и пополняется в последующих работах.

## raw.stream

- **Имя:** `raw.stream`.
- **Архитектура и слой:** слой сырых данных на диске стенда (локальное файловое хранилище).
- **Где лежит:** `~/stand/data/raw/stream/dt=YYYY-MM-DD/hour=HH/part-*.jsonl.gz`; путь в контейнере `/data/raw/stream/...`.
- **Формат:** JSON Lines, сжатие gzip; одно событие `marketdata` в строке.
- **Партиционирование и сортировка:** каталог `dt` — дата **получения UTC**, `hour` — час получения UTC; явная сортировка по полям внутри файла не гарантируется, записи добавляются по мере опросов.
- **Источник:** MOEX ISS, фильтр `stock/shares/TQBR`, программа `collector/src/main.py`, режим `record`; опрос каждые 10 секунд (настроенное значение проверить в `.env`).
- **Потребители:** ЛР2 — чтение в DuckDB, преобразование в Parquet; ЛР3 — перенос сырья в объектное хранилище; ЛР6 — воспроизведение и сверка потока. На ЛР1 данные проверяются командами `zcat`/`jq`.
- **Свежесть:** сборщик запрашивает данные примерно раз в 10 секунд во время доступности API. Публичный ISS может выдавать данные с задержкой ~15 минут; фактическая свежесть относительно источника не замерена. При закрытии торгов новых событий может не быть.
- **Рост в 1000 раз:** **TODO**: после суток записи оценить объём файлов/сутки и размер партиции. Возможные ограничения — лимит 20 ГБ, число мелких файлов и время чтения; выбрать первое по реальным замерам, а не предположению.
- **Фактическое состояние на 12.10.2026:** 122 закрытых `.jsonl.gz`, `du -sh` ≈33 MiB, в закрытых файлах этой даты 206601 строк; отсутствие дублей `event_key` проверено (0).

## raw.history

- **Имя:** `raw.history`.
- **Архитектура и слой:** слой сырых исторических данных на диске стенда; отдельный набор, не объединяется с `raw.stream`.
- **Где лежит:** `~/stand/data/raw/history/dt=YYYY-MM-DD/candles-<SECID>-page-<OFFSET>.jsonl.gz`; путь в контейнере `/data/raw/history/...`.
- **Формат:** JSON Lines, сжатие gzip; одно событие минутной свечи `candles` в строке.
- **Партиционирование и сортировка:** `dt` — дата события `begin`, приведённого в UTC; имена файлов соответствуют бумаге и странице API. Специальная сортировка содержимого не гарантируется.
- **Источник:** MOEX ISS, `collector/src/main.py`, разовый режим `backfill`, исторические минутные свечи по каждой бумаге TQBR за заданный интервал.
- **Потребители:** ЛР2 — отдельный набор `parquet.candles`; в ЛР3 хранится как сырьё исторического среза. **Не является источником таблицы очищенных событий marketdata**.
- **Свежесть:** пополняется при ручном запуске `backfill`, не является онлайн-потоком. Границы выгрузки задаются переменными `COLLECTOR_HISTORY_FROM` и `COLLECTOR_HISTORY_TO`.
- **Рост в 1000 раз:** **TODO**: оценить по размеру свечей, количеству бумаг и числу файлов за день. При росте может первым возникнуть ограничение по количеству объектов/листингу и скорости HTTP-загрузки; подтвердить числами.
- **Фактическое состояние на 12.10.2026:** 5374 закрытых `.jsonl.gz`, `du -sh` ≈38 MiB; каталоги дат с `2026-10-01` по `2026-10-09`. **В каталогах девяти UTC-дат имеется 919 594 строки свечей; семь будних дат и две торговые сессии выходного дня. Проверка полноты по каждому SECID и пагинации остаётся открытой**.


## parquet.events

- **Имя:** `parquet.events` (ЛР2, нормализованные снимки `marketdata` TQBR).
- **Путь:** `~/stand/data/duckdb/parquet/events/event_date=YYYY-MM-DD/*.parquet` (`/data/duckdb/parquet/events` внутри DuckDB).
- **Источник:** `raw.stream` с отдельной обработкой часов по времени получения, преобразование `jobs/export_parquet.py`; `jobs/to_parquet.sql` — контрольный тест одного часа.
- **Схема:** Avro v1 (`schemas/event.avsc`, 59 полей без `NUMTRADES`), в Parquet дополнительно `event_date` по дате `event_time` в UTC.
- **Версии схемы:** для **новых суток** предусмотрена Avro v2 (`schemas/event_v2.avsc`, добавлен `NUMTRADES` с `default=null`). Обычно новая дата загружается командой `python3 jobs/export_v2_day.py --day YYYY-MM-DD`. Для учебной замены партиции 2026-10-26 доступны `--snapshot-incomplete-day --replace-existing-day`: после проверки v2 прежняя партиция перемещается в `data/duckdb/parquet_v1_backup/`. Такой результат — частичный снимок закрытых часов, а не полные UTC-сутки. После записи разнородные файлы читаются с `union_by_name=true`. Фактическая v2-партиция: **2026-10-26**, частичный снимок двух часов получения (16 и 17 UTC), 97 210 событий, 2 файла; для всех записей `NUMTRADES` ненулевое. Другие даты v1 остались прежними, совместное чтение с `union_by_name=true` успешно, контрольная сумма файла за 19 октября сохранена.
- **Формат/сжатие:** Parquet, ZSTD, `ROW_GROUP_SIZE=100000` при контрольном преобразовании. Временные поля приводятся к `TIMESTAMP_MS` после нормализации в UTC (timezone-naive UTC).
- **Результат доп. эксперимента ЛР2 / рекомендация для ЛР3:** на 61 644 событиях проверены 4 кодека × 3 размера row group (12 файлов, три запроса каждый). По компромиссу между размером и скоростью выбраны **ZSTD / ROW_GROUP_SIZE=32768**: 3 450 955 байт, 2 группы, медиана 0,004 с. Минимальный размер: GZIP / 32768 — 3 364 666 байт (0,005 с); минимум медианного времени: SNAPPY / 32768 — 4 663 884 байта (0,003 с). Фактический набор ЛР2 ранее создан с ZSTD / ROW_GROUP_SIZE=100000 — рекомендация для ЛР3 не означает перезапись данных ЛР2.
- **Свежесть и сортировка:** Parquet обновляется после ручного запуска пакетного преобразования, а не непрерывно; последняя подтверждённая полная выгрузка v1 и частичный снимок v2 проведены 26.10.2026. Явная сортировка записей внутри файла не задаётся.
- **Партиции:** по дате **события**, а не по дате получения; файлы отдельных часов имеют имена `recv-YYYYMMDD-HH_*.parquet`.
- **Повторный запуск:** пакет выгружается во временный каталог, проверяется, затем заменяются только файлы этого же часа, без удаления соседних часов.
- **Потребители:** SQL-анализ DuckDB в ЛР2, выгрузка в объектное хранилище в ЛР3.
- **Проверка 19.10.2026 16:00–16:59 UTC:** 61 644 строки, 61 644 уникальных ключа, один файл 3 238 018 байт. Первоначальная полная загрузка v1 (26.10.2026): 139 часовых порций, 139 Parquet-файлов; после учебной замены одного файла 26.10.2026 двумя файлами v2 в активном наборе ожидается 140 Parquet-файлов, размер каталога по `du -sh` **370 MiB** (округлённо); по проверке `union_by_name=true` суммарно **7 604 846 строк** (включая неполный снимок v2 за 26 октября). **Точный размер всех активных Parquet-файлов по `find ... -printf '%s\n'`: 390 869 219 байт** (26.10.2026, после v2; резервная v1-партиция не учитывается).
- **Рост в 1000 раз:** грубый сценарный ориентир по конкретному часу получения 19.10.2026 16 UTC: 3 238 018 байт Parquet на 61 644 события; при 1000-кратном числе идентичных по структуре событий и сохранении того же коэффициента — около 3,24 ГБ/час. Это экстраполяция **не измерение**; дисковая ёмкость, число и размер файлов, стоимость создания групп, число запусков DuckDB и операции со списками файлов потребуют отдельного нагрузочного теста. При первоначальной попытке чтения всего raw получен код 137 (предположительно ограничение памяти).

## parquet.candles

- **Имя:** `parquet.candles` (ЛР2, минутные исторические свечи MOEX ISS).
- **Путь:** `~/stand/data/duckdb/parquet/candles/event_date=YYYY-MM-DD/*.parquet`.
- **Источник:** `raw.history`, отдельно от `marketdata`; тест одной даты в `jobs/to_parquet_candles.sql`, полная обработка по датам — `jobs/export_parquet.py`.
- **Схема:** `open`, `close`, `high`, `low`, `value`, `volume`, `begin`, `end`, `SECID`, `BOARDID`, `event_key`, `event_time`, `received_at`, `source`, `event_date`.
- **Время:** исходные `begin`/`end` оставлены строками MSK; `event_time` и `received_at` нормализованы в UTC и записаны как `TIMESTAMP_MS` без timezone-аннотации.
- **Формат/сжатие:** Parquet, ZSTD; партиция `event_date` по UTC-времени события.
- **Свежесть и сортировка:** пакетное обновление после выгрузки `backfill`, не онлайн. Явная сортировка строк внутри файлов не задана.
- **Повторная обработка:** файлы конкретной даты замещаются после успешной проверки, без накопления копий.
- **Потребители:** запросы и сравнения DuckDB в ЛР2, передача исторического набора в ЛР3.
- **Проверка 02.10.2026:** 112 622 строки, 112 622 уникальных ключа, один файл 1 994 033 байта; повторный прогон оставил один файл. Полная история (26.10.2026): 9 дат, 9 Parquet-файлов, размер каталога по `du -sh` **16 MiB** (округлённо); подтверждено **919 594 строк** по девяти исходным датам и равенству строк для каждого пакета. **Точный размер девяти активных Parquet-файлов: 16 416 853 байта** (26.10.2026).
- **Рост в 1000 раз:** экспериментально не проверялся. Суммарная история на 9 дат занимает около 16 МиБ Parquet по `du -sh`; при простой линейной экстраполяции это около 16 ГиБ на сопоставимое 1000-кратное количество свечей (без учёта изменения сжатия и размера групп). Возможные ограничения — число мелких файлов и скорость обработки исторического backfill; первый узкий ресурс подтвердить нагрузочным тестом.
