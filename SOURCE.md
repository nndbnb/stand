# Паспорт источника: MOEX ISS (вариант №12)

**Статус:** черновик по состоянию на 12.10.2026. Сведения о фактически полученных данных взяты из вывода стенда. Полные суточные замеры и контроль полноты исторического среза ещё требуются.

## Доступ

- Источник: информационно-статистический сервер Московской биржи (MOEX ISS).
- Тип получения потока: опрос HTTP API `marketdata` с периодом не менее 10 секунд.
- Адрес: `https://iss.moex.com/iss/engines/stock/markets/shares/boards/TQBR/securities.json?iss.meta=off&iss.only=marketdata&limit=1000`.
- Исторический срез: минутные свечи отдельного набора, по каждой бумаге из доски TQBR.
- Шаблон запроса истории: `https://iss.moex.com/iss/engines/stock/markets/shares/boards/TQBR/securities/{SECID}/candles.json?interval=1&from={DATE_FROM}&till={DATE_TO}&start={OFFSET}`.
- Заявленный период загрузки истории: **01.10.2026–09.10.2026**. На диске обнаружены каталоги `dt=2026-10-01` … `dt=2026-10-09` (всего 9 календарных дат). **Семь будних дней и две дополнительные даты торгов выходного дня подтверждены; полнота по каждой бумаге отдельно не проверена.**
- Глубина доступной истории: сервер выдаёт исторические свечи за запрошенный диапазон; фактическую глубину доступности для TQBR необходимо проверить отдельно. В методических указаниях указан способ догрузки минутных свечей.
- Соотношение схем: история **не эквивалентна** потоку; свечи (`candles`) и снимки `marketdata` — разные наборы. Свечи не используются для восстановления отсутствующих строк `marketdata`.

## Лицензия и условия использования

- По методическим указаниям: публичные сведения MOEX ISS предоставляются для ознакомительного использования; иные условия использования — по договору с биржей.
- Собранные данные не публикуются. Рабочий репозиторий с результатами лабораторных — закрытый.
- Для неавторизованного доступа к публичному ISS в методических указаниях указана задержка рыночных данных около 15 минут. Фактическое отставание следует оценивать по наблюдениям.

## Лимиты и представление клиента

- Опрос доски TQBR: не чаще 1 раза в 10 секунд; `COLLECTOR_POLL_SECONDS=10` (проверить значение в локальном `.env`).
- Исторические свечи: не чаще 1 запроса в секунду; ответ разбивается на страницы.
- Ответы HTTP 429 и 5xx: повтор с увеличивающейся паузой.
- `User-Agent`: задаётся переменной `COLLECTOR_USER_AGENT`, содержит название сборщика и контакт. **Фактический контакт не записываем в отчёт; убедиться, что он задан в локальном `.env`.**
- Объём слоя `stream` + `history`: `COLLECTOR_RAW_LIMIT_GB=20` по заданию. Проверить в `.env`.
- Служба имеет ограничение памяти 512 МБ по контракту стенда.

## Схема события

### Поток `raw.stream` (marketdata)

Событие — состояние конкретной бумаги доски TQBR с новым значением `SYSTIME`. Время источника трактуется как `Europe/Moscow` и переводится в UTC. Ключ строится из доски, `SECID` и приведённого к UTC времени `SYSTIME`.

| Поле | Тип в сохранённом JSON / ожидаемый тип | Смысл | Реальный пример |
|---|---|---|---|
| `event_key` | string, обязательное | Идемпотентный ключ события | `moex:TQBR:ABIO:2026-10-12T14:29:01.000Z` |
| `event_time` | string ISO 8601 UTC, обязательное | Время биржевого события из `SYSTIME` | `2026-10-12T14:29:01.000Z` |
| `received_at` | string ISO 8601 UTC, обязательное | Время получения сборщиком | `2026-10-12T14:29:05.862Z` |
| `source` | string, обязательное | Ось источника | `moex` |
| `SECID` | string | Код бумаги | `ABIO` |
| `BOARDID` | string | Доска торгов | `TQBR` |
| `SYSTIME` | string, московское локальное время | Время обновления исходной строки | `2026-10-12 17:29:01` |
| `BID` | number/null | Цена заявки на покупку | `44.28` |
| `OFFER` | number/null | Цена заявки на продажу | `44.38` |

Их типы и nullable-статус подлежат полной проверке по накопленным событиям перед ЛР2 (поля, имеющие `null` в одном образце, нельзя надёжно типизировать по одному примеру).

- Идемпотентный ключ: `event_key = 'moex:TQBR:' + SECID + ':' + event_time`.
- Время события: `SYSTIME`, исходное московское время, конвертация в UTC с точностью до миллисекунд в строковом представлении. В примере локальное `17:29:01` соответствует UTC `14:29:01`.
- Время получения: `received_at`, UTC.

### История `raw.history` (candles)

- Отдельная схема: минутная свеча по бумаге; поля по спецификации методички — `open`, `close`, `high`, `low`, `value`, `volume`, `begin`, `end`, дополнительно `SECID`, `BOARDID` и четыре обязательных служебных поля.
- Ключ: `moex:TQBR:candle:{SECID}:{event_time}`, где `event_time` берётся из `begin`, приведённого к UTC.
- **Пример реального содержимого файла `history` не предоставлен.** Проверить схему по одной строке `zcat` перед окончательной сдачей.

## Фильтр потока и объёмы

- Фильтр задания: `SOURCE_FILTER=stock/shares/TQBR`.
- Фильтрация по доске выполняется прежде всего **на стороне ISS**, поскольку URL уже содержит `boards/TQBR`. Сборщик также проверяет `BOARDID`.
- Важно: `got` из журнала (например, 512) — **строки уже отфильтрованного ответа TQBR**, а `kept` (например, 177–302) — новые значения `SYSTIME` после удаления повторов. Это **не** объёмы «до/после фильтра рынка»; использовать отношение `kept/got` для доли фильтра неправильно.
- Для объёма всего потока до серверного фильтра, если он недоступен, методичка разрешает использовать справочную оценку с пометкой о её происхождении.

## Известные дефекты

- Значения `SYSTIME` приходят в московском времени без обозначения зоны → переводятся в UTC.
- Строки снимка повторяются между опросами → записываются только события с новым `SYSTIME` для соответствующего `SECID`.
- У ряда полей есть `null` (например, `BIDDEPTH`, `OFFERDEPTH`, `CLOSEPRICE`) → сохраняются как `null`, не заменяются выдуманными числами.
- История и поток имеют разные схемы → хранятся в отдельных каталогах и не смешиваются.
- В ранней версии сборщика возникали ошибки повторной страницы `marketdata` при попытке постраничного чтения → версия v02 читает этот блок одним запросом. **Прямой повторный запрос пользователя вернул 512 строк в `securities` и 512 строк в `marketdata`**. Совпадение подтверждает текущий размер ответа, но не исключает ограничение выдачи сервером; проверка смещения `start=512` остаётся полезной.
- При отсутствии торгов обновлений может не быть → `kept=0` допустимо.
