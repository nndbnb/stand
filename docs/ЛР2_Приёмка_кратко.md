## 1. Avro: схема и две версии в Git

```bash
python3 - <<'PY'
import json
for path in ('schemas/event.avsc', 'schemas/event_v2.avsc'):
    with open(path, encoding='utf-8') as f:
        fields = json.load(f)['fields']
    print(path, 'полей:', len(fields))
    for x in fields:
        if x['name'] in ('event_key', 'event_time', 'NUMTRADES'):
            print(' ', x)
PY
git log --oneline -- schemas/event.avsc schemas/event_v2.avsc
python schemas/check.py --day 2026-10-19 --hour 16
```

Ожидается: **59 полей v1, 60 полей v2**; `event_time` — `timestamp-millis`; `NUMTRADES` добавлен в v2. Проверка Avro: **61 644 записей**, ошибок и расхождений **0**, `RESULT: OK`.

## 3. JSONL.gz и Parquet: размеры и три замера

```bash
cat jobs/benchmark_raw.sql

for f in data/duckdb/benchmark_{raw,parquet}_{1,2,3}.txt; do
  echo "== $f =="; tail -n 2 "$f"
done
```

Показать за одну порцию **61 644 события**:

| | JSONL.gz | Parquet |
|---|---:|---:|
| Размер | 10 714 563 байта | 3 238 018 байт |
| 3 времени, с | 0,231 / 0,228 / 0,228 | 0,005 / 0,005 / 0,006 |

Агрегаты запроса совпали; Parquet быстрее в этом тесте примерно в **45,6 раза**. В v1 нет `NUMTRADES`, поэтому наборы полей при сравнении размера не полностью идентичны.

Ожидается: **v1 → v2 OK**, **v2 → v1 OK**, `RESULT: OK`; старые Parquet-даты — `NUMTRADES=NULL`, дата **26.10.2026** — **97 210 ненулевых** `NUMTRADES`; контрольная сумма v1 — `OK`.

Это подтверждает чтение разных схем, но **формально отличается** от указанного способа записи новых суток.
