# ЛР3/ЛР4 — применение изменений и сбор результатов WSL

Рабочая ветка: `lab3-lab4`. Скрипт `scripts/lr34_apply.sh` запущен **только вручную**; он не выполнялся на пользовательском WSL в процессе редактирования Git.

## 1. Забрать изменения

```bash
cd ~/stand
git fetch personal lab3-lab4
git switch lab3-lab4
git pull --ff-only personal lab3-lab4
source .venv/bin/activate
```

Если `source .venv/bin/activate` не сработает, проверьте интерпретатор, которым ранее запускали `jobs/iceberg_load.py`: в нём должен быть `boto3`. Не печатайте содержимое `.env` в публичном логе.

## 2. Безопасная предварительная проверка (данные не меняет)

```bash
bash scripts/lr34_apply.sh --check
```

Это синтаксическая проверка Python, проверка Compose, dry-run планов, инвентаризация S3, сравнение raw/clean за 19.10, запросы с отсечением партиций, dry-run retention. Отчёт — в `docs/evidence/lr34-<UTC>/`, полные логи — в игнорируемом Git каталоге `data/lr34/`.

## 3. Пересборка данных (изменяет clean и Iceberg)

Сначала проверьте свободное место в WSL и на диске Windows для резервной копии `data/raw`:

```bash
df -h ~/stand /mnt/c
du -sh data/raw
bash scripts/lr34_apply.sh --apply --backup-dir /mnt/c/Users/Public/lr34-backups
```

`--apply` требует каталог под `/mnt/<диск>/`. Он **перед изменениями** копирует `data/raw` на Windows-диск и прекращает работу при ошибке копирования. Затем запускает профиль ЛР4, проверяет перенос raw, пересоздаёт допустимые суточные `clean.events`, создаёт отдельный `clean.history` из свечей и повторно загружает `clean.events` в Iceberg. Применение может занять много времени и создать новые Iceberg snapshots. **Не запускайте до проверки доступного места.**

Скрипт НЕ вызывает `retention --apply`, `expire_snapshots` и не запускает конфликтующие конкурентные записи; эти действия требуют отдельного плана безопасности.

## 4. Опубликовать результаты проверки в Git

```bash
git add docs/evidence/
git commit -m "test: lr34 WSL acceptance results"
git push personal lab3-lab4
```

Публикуются только `summary.md` и `inventory.json`, **не** `.env`, логи и биржевые данные. Если работа завершилась ошибкой, полный лог доступен локально по пути, напечатанному как `FULL_LOG=...`; передавать полный лог публично без просмотра нежелательно.

## Оставшиеся ограничения по PDF

- Проверка наличия D+1 в S3 — необходимое, но недостаточное условие полноты суток: файл D+1 может быть частичным.
- Если в S3 отсутствуют исходные часы, скрипт не может восстановить их самостоятельно.
- Свечи `raw.history` и биржевые снимки `raw.stream` имеют разные схемы, поэтому очищаются в разные наборы. `lake.clean.events` содержит только marketdata.
- Историческая точка восстановления *после ЛР1* не может быть создана задним числом. Новая копия на Windows отвечает только за актуальную внешнюю резервную копию.
- Дополнительные задания (+1 ЛР3, +2 ЛР4) не являются выполненными после запуска этого скрипта автоматически.
- Количество всех объектов Iceberg до/после ранее выполненного `expire_snapshots` уже невозможно измерить задним числом.
