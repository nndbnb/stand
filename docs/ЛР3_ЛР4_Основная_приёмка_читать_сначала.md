Подготовка среды

Открыть терминал WSL. Убедиться, что выбрана ветка lab3-lab4, сервисы стенда доступны, виртуальное окружение Python активировано.

Команды:
cd ~/stand
git pull --ff-only personal lab3-lab4
source .venv/bin/activate
git branch --show-current
docker compose ps

Порядок приёмки ЛР3

1. Показать конфигурацию S3=seaweedfs и состав COMPOSE_FILE.
2. Показать сервисы lab3 и bucket lake в интерфейсе SeaweedFS.
3. Открыть соглашения по префиксам и партициям в CATALOG.md.
4. Показать синхронизацию закрытых файлов из collector через boto3.
5. Продемонстрировать равенство локальных файлов и объектов S3.
6. Объяснить правила очистки MOEX, дедупликацию, приведение типов и UTC.
7. Показать подготовку суток D из сырья D и D+1, постоянное имя Parquet.
8. Показать обработанный исторический срез и количественную сверку событий.
9. Сравнить два запроса DuckDB с предикатом и без него.
10. Показать сроки хранения, размер данных и доступный объём диска.
11. Запустить retention с параметром --dry-run.
12. Показать наборы данных и потребителей в CATALOG.md.

Команды:
docker compose --profile lab3 ps
docker compose run --rm -T --no-deps --entrypoint python collector /app/src/lake_audit.py
python3 jobs/lr34_inventory.py
python3 jobs/verify_clean_counts.py --day 2026-10-19
python3 jobs/verify_clean.py --day 2026-10-19
python3 jobs/retention.py --layer clean --days 2 --dry-run
du -sh data/* 2>/dev/null
df -h
docker system df

Результат сверки 03.11.2026: 10242 закрытых raw-файла и столько же объектов S3, 1415994017 байт, расхождений по именам и размерам нет. За 19.10.2026 в clean находится 724665 записей и столько же уникальных ключей.

Порядок приёмки ЛР4

1. Показать ENGINE=duckdb и файлы конфигурации профиля.
2. Показать сервисы lab4 и подключение к Lakekeeper.
3. Открыть определение таблицы lake.clean.events и скрытое партиционирование.
4. Показать программу загрузки суточных и часовых интервалов.
5. Выполнить SQL-запросы к Iceberg с фильтром по времени и без него.
6. Показать конфигурацию Spark и доступные снимки.
7. Объяснить результаты контрольной вставки, VERSION AS OF и rollback.
8. Объяснить компакцию data-файлов по результатам опыта.
9. Показать результаты expire_snapshots в NOTES.md и текущее состояние снимков.
10. Показать поле NUMTRADES и сохранение прежних Parquet-файлов в зафиксированном опыте.
11. Открыть CATALOG.md, NOTES.md и раздел «Связи сервисов».

Команды:
docker compose --profile lab4 ps
python3 jobs/iceberg_load.py --all --dry-run
docker compose run --rm -T duckdb -init init.sql -bail -f /dev/stdin < jobs/iceberg_benchmark.sql
docker compose run --rm -T spark /opt/spark/bin/spark-sql -e "SELECT snapshot_id, committed_at, operation FROM lake.clean.events.snapshots ORDER BY committed_at"
docker compose run --rm -T spark /opt/spark/bin/spark-sql -e "SELECT partition, count(*) AS files, avg(file_size_in_bytes) AS avg_bytes FROM lake.clean.events.files GROUP BY partition ORDER BY partition"
docker compose run --rm -T spark /opt/spark/bin/spark-sql -e "DESCRIBE TABLE lake.clean.events"

Результаты опыта 02.11.2026: DuckDB с временным предикатом прочитал два файла вместо девятнадцати. В процессе rollback восстановлено прежнее количество строк. Компакция объединила пять файлов одной партиции в один, после expire_snapshots остался один снимок. Эволюция схемы добавила NUMTRADES без перезаписи активных файлов на момент опыта. После повторной загрузки 03.11.2026 текущие снимки и число файлов могут отличаться.

Условия использования результатов

На защите используют безопасные запросы чтения и dry-run. Повторная массовая перезагрузка, удаление объектов S3, выполнение expire_snapshots и откат текущей таблицы для демонстрации не требуются.

Полнота данных определяется наличием исходного сырья. Для пересчёта 23 и 27 октября необходимы отсутствующие в архиве файлы следующих суток. При предъявлении предварительных условий ЛР3 отдельно показывают датированную точку восстановления после ЛР1 и внешнюю копию сырья.

Все приведённые числовые результаты относятся к указанным датам измерения. Актуальные показатели при необходимости получают командами проверки перед защитой.
