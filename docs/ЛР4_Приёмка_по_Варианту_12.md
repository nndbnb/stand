3. Чтение прошлого снимка и откат записи

Продемонстрировать в NOTES.md протокол выполненного опыта 02.11.2026 и файл jobs/iceberg_bad_insert.sql.

До контрольной вставки: 7 814 151 строка.
После вставки: 7 814 661 строка.
VERSION AS OF прежнего snapshot_id: 7 814 151 строка.
После rollback_to_snapshot: 7 814 151 строка.

Показать историю сохранившихся снимков:
docker compose run --rm -T spark /opt/spark/bin/spark-sql -e "SELECT snapshot_id, committed_at, operation FROM lake.clean.events.snapshots ORDER BY committed_at"

Прежний снимок контрольного опыта был удалён при последующем expire_snapshots, поэтому повторный VERSION AS OF по его идентификатору сейчас не выполняется. Новую ошибочную запись и откат для демонстрации не создавать.

4. Компакция и устаревание снимков, показатели до и после

Предъявить результаты из NOTES.md за 02.11.2026.

Компакция rewrite_data_files: 20 активных файлов до операции, 16 после. В партиции 27.10.2026 пять файлов объединены в один.

Устаревание expire_snapshots: 22 снимка до операции, 1 после.

Показать текущее состояние без изменения данных:
docker compose run --rm -T spark /opt/spark/bin/spark-sql -e "SELECT partition, COUNT(*) AS files, AVG(file_size_in_bytes) AS avg_bytes FROM lake.clean.events.files GROUP BY partition ORDER BY partition"
docker compose run --rm -T spark /opt/spark/bin/spark-sql -e "SELECT COUNT(*) AS snapshots FROM lake.clean.events.snapshots"

В исходных протоколах отсутствуют сопоставимые замеры полного числа объектов таблицы непосредственно в bucket до и после expire_snapshots. Значения активных data-файлов не заменяют этот показатель. Не указывать его как измеренный.
